最容易踩的坑：domain 变量格式

如果 domain 填成纯文本 111911.xyz，页面会一直卡在启动动画，并提示 「环境变量domain必须是JSON类型」。正确写法是带方括号和引号的 JSON 字符串： ["111911.xyz"]。多个域名就写成 ["a.com","b.com"]，每个都要用双引号。

4. 邮件收发链路

收信（外部 → @111911.xyz）

  • 由 Cloudflare Email Routing 免费提供，catch-all 全收规则转发给 Worker。
  • 需要的 DNS：MX 记录（自动锁定）、SPF、DKIM。这些在启用 Email Routing 时由 Cloudflare 自动添加。
  • 任何前缀的地址都能收信，例如 abc@111911.xyz、任意名@111911.xyz。

发信（@111911.xyz → 外部）

  • 走 Resend，免费额度 每天 100 封、每月 3000 封。
  • API Key 已填入后台：系统设置 → 邮件设置 → Resend Token。
  • Resend 侧域名状态必须为 verified，否则发信会失败。
  • 站内互发（@111911.xyz 之间）不消耗 Resend 额度。
Cloudflare 原生发信需要付费

Cloudflare 自己的 Email Sending 功能要 Workers Paid（$5/月起）。当前用的是免费方案，所以走 Resend。 如果以后升级付费，可以改成绑定 send_email，不依赖第三方。

但 mail.111911.xyz 的云朵必须保持开启

这个自定义域指向的是 Worker，Worker 本身没有源站服务器。把它改成灰色「仅 DNS」，请求会直接发往不存在的源站， 整站就打不开了。橙色云朵是 Worker 自定义域能正常工作的前提条件，不能关。

6. 日常维护

查看发信额度

登录 resend.com，能看到当天已发数量和投递状态。 额度用完后当天无法继续发信，次日零点（UTC）重置。

添加新邮箱账号

后台 → 管理 → 全部用户 → 添加。也可以开放注册（系统设置 → 用户注册）。 注意开放注册意味着任何人能用你的域名注册，会共享发信额度，有被滥发拉黑域名的风险。

修改站点标题和 logo 文字

后台 → 管理 → 系统设置 → 网站标题。这个字段同时驱动左上角 logo 文字和浏览器标签页标题， 改成什么就显示什么，无需改代码。

更新程序版本

  1. 打开 github.com/zhenmafan886/cloud-mail，点 Sync fork 同步上游更新。
  2. Cloudflare 会自动检测到 push 并重新构建部署。
  3. 如果构建失败，Cloudflare 会保留上一个成功版本，站点不会中断。

注意：本仓库对侧边栏菜单做过定制（新增「帮助」入口），Sync fork 时如果菜单文件冲突， 需要保留本地改动，只合并上游其他更新。

7. 常见故障排查

页面一直转圈打不开

  • 最常见原因：domain 变量格式不对，检查是否为 ["111911.xyz"]。
  • 其次检查 D1、KV、R2 三个绑定是否齐全，缺任何一个接口都会报错。
  • 如果接口返回「KV数据库未绑定」，说明绑定表被人重置了，去 Worker 设置 → 绑定 里核对是否为 5 项： ai、assets、db、forward、kv、r2。

能收信但不能发信

  • 后台系统设置里「邮件发送」开关是否开启。
  • Resend Token 是否填写、是否对应当前域名。
  • Resend 域名状态是否 verified。
  • 今天是否已用满 100 封额度。

访问时频繁出现「人机验证」

  • 来源：Cloudflare 安全规则里的一条自定义规则触发了 JavaScript 质询。
  • 排查位置：Cloudflare → 111911.xyz → 安全性 → 安全规则。
  • 本项目曾有一条「拦截非法请求-放行蜘蛛」规则（境外 IP + 带 X-Forwarded-For 时触发质询），已将其禁用。
  • 若再次出现，检查是否有人重新启用了类似规则，或「浏览器完整性检查」是否处于开启状态。

修改后台设置提示失败

通常是 admin 变量与当前登录账号不一致导致没有管理权限。 确认 admin 的值和你登录的邮箱完全相同。

数据在哪、要不要备份

所有邮件、用户、设置都存在 D1 数据库 cloud-mail 里，附件在 R2。 项目没有内置备份功能，重要邮件建议在后台导出或本地另存。

9. 安全提醒

  • jwt_secret 泄露等于别人可以伪造登录状态，怀疑泄露就立即在控制台换掉。
  • Resend API Key 存在数据库里，管理员账号可以看到，不要随意把管理员权限给别人。
  • 当前 Resend Key 是全权限，更保险的做法是在 Resend 新建一个只能发信的 Key 替换掉。
  • 开放注册前想清楚：任何人都能用 @111911.xyz 发信，被用来发垃圾邮件会导致整个域名被拉黑。
  • 本文档已设置 noindex，不应出现在搜索引擎结果里；但页面上仍有账号名等信息，仍按内部文档对待。

10. 本次部署踩坑记录

  1. 坑domain 填纯文本导致页面卡死，必须写 JSON 数组格式。
  2. 坑初始 admin 填了未注册的 admin@111911.xyz，导致登录后没有管理菜单，改成实际注册的邮箱才生效。
  3. 坑Resend 域名页的 DKIM 值在浏览器里显示为省略号，没法直接复制，最后通过 Resend API 取到完整值才配对。
  4. 坑先只绑了 forward 没绑 email，站外发信会报「未配置发信服务」。
  5. 最坑最初绑定是在控制台手动加的，而仓库 wrangler.toml 里 db/kv/r2 是注释状态。 推送代码触发重新部署后，wrangler 按配置重置绑定，db/kv/r2 全部丢失，站点卡在启动动画， 接口报「KV数据库未绑定」。解决办法是把三条绑定写进 wrangler.toml，已修复。
  6. 经验以后凡是手动在控制台加的绑定，都要同步写进 wrangler.toml，否则下次部署会被覆盖。

11. 管理员密码忘记了怎么办

先明确一点：这套系统没有「忘记密码」和邮件找回功能

仓库里没有任何 forget / reset / forgot 相关代码，登录页也没有「忘记密码」入口。 密码忘了，只能靠下面三条路自救。建议现在就把这一节读一遍，并提前做好文末的两条预防措施。

密码是怎么存的（理解这一点才好手工重置）

用户表在 D1 数据库 cloud-mail 的 user 表中，密码不存明文，存的是两个字段：

  • salt：16 字节随机数的 Base64 字符串
  • password：对「salt 字符串 + 明文密码」拼接后做 SHA-256，再 Base64 编码的结果
password = base64( SHA-256( salt + 明文密码 ) )

所以只要同时改写 salt 和 password 两个字段，就能把密码设成任意值，不需要知道原密码。

方案 A：直接在 D1 控制台改密码（最可靠，不依赖登录）

位置：Cloudflare → Workers & Pages → D1 → cloud-mail → Console。

把下面这条 SQL 整条粘贴执行，执行后 sand@111911.xyz 的密码会变成 Temp123456：

UPDATE user
SET salt = '6BRja3+LSy6cDQZ6xvEmMQ==',
    password = '/WzI8sZOIxXSYIWckA8RMJ6WofatXgzCQ00fFtSbhp8='
WHERE email = 'sand@111911.xyz';
执行后立刻登录，第一件事就是改成自己的密码

Temp123456 是本文档公开写明的临时密码，只用于找回那一刻。 登录后马上到「个人设置」改掉，不要长期保留。

如果提示表不存在，先执行 SELECT name FROM sqlite_master WHERE type='table'; 核对表名。 如果想换成别的临时密码，把 salt 换成任意新的 Base64 字符串，再按上面的公式重算 password 即可，两者必须配套。

方案 B：借 admin 环境变量「换一个管理员」

管理员身份不是写在数据库里的，而是由环境变量 admin 的邮箱值决定：哪个账号的邮箱与该值相同，哪个账号就是管理员。 所以可以绕开忘记密码的账号：

  1. 用任意邮箱注册一个新账号，例如 rescue@111911.xyz（系统设置 → 用户注册 需为开启状态，或直接在注册页注册）。
  2. Cloudflare → Workers → cloud-mail → 设置 → 变量和机密，把 admin 改成这个新邮箱。
  3. 保存后等待生效（或重新部署一次），新账号立刻拥有管理菜单。
  4. 进入「用户列表」，重置原来的 sand@111911.xyz 密码。
  5. 最后把 admin 改回 sand@111911.xyz，并删除临时账号。

这个方案完全不碰数据库，但需要能正常注册新账号。注册码若为开启状态，先关掉或拿到注册码。

方案 C：还有设备保持登录

如果某个浏览器还没退出登录，直接进「个人设置」改密码； 若该账号有管理权限，也可以在「用户列表」里重置其他账号。但会话一旦过期就失效，窗口期很短。

两条预防措施，建议现在就做
  • 留一个备用管理员：多注册一个账号，需要时把 admin 变量切过去应急，相当于给自己留了后门。
  • 密码和上面的 SQL 存进密码管理器：这套系统没有找回通道，忘了就只剩改数据库一条路。
